Cerrar una terminal sin cerrar las vecinas

Candidata compilada y revisada parcialmente. No instalada ni aceptada. La autorización del usuario para esta corrección exige terminar la terminal elegida y sus procesos, en lugar de ocultarla conservando el shell.

Acción y efecto

En Terminal Normal, Space b d y Space w q solicitan terminar la ventana de tmux que muestra la pestaña actual. Todos los paneles de tmux de esa ventana terminan. Las ventanas vecinas y sus layouts se conservan. El cierre de archivos conserva sus comprobaciones de guardado; Ctrl+w c continúa cerrando una ventana nativa sin terminar su shell.

Este dibujo describe el contrato; no es una captura ni evidencia de ejecución. Terminar la última ventana no crea un shell nuevo. Se puede pedir otro explícitamente con :TmuxReconnect. En una adicional terminada se crea otra con identidad nueva si la principal vive; si ambas terminaron, esa acción enfoca y recrea la principal. Los clientes adicionales terminados se retiran cuando ya no tienen vistas ni operaciones pendientes. Un proceso que ya se haya separado de su terminal o ignore sus señales puede sobrevivir: el alcance implementado es el cierre de la ventana mediante tmux, no un supervisor de todos sus descendientes.

Por qué se bloqueaba

La reproducción en la aplicación instalada mostró «Identidad de terminal compartida; buffer conservado». Un buffer de archivo vacío sí se cerró. En el código, vim_delete_terminal_buffer rehúsa renovar la identidad de un cliente de terminal cuando el mismo proyecto conserva layouts de otras pestañas. Una pestaña de tmux y el cliente que la muestra son objetos distintos.

Controles de alcance

La solicitud conserva IDs exactos de servidor, sesión, ventana y panel, junto con dispositivo e inode del socket. El trabajador vuelve a comprobarlos y evalúa el destino activo en la cola de tmux inmediatamente antes de kill-window. Las ventanas enlazadas a otra sesión se rechazan. No se utiliza kill-session, un índice de pestaña ni un destino que se vuelva a resolver tras cambiar de foco. Un resultado incierto se informa y no se reintenta automáticamente.

Mientras se confirma el cierre, TWR rechaza nuevas teclas con un mensaje explícito para no enviarlas al shell vecino. No hay animación ni espera decorativa. El zoom y las operaciones pendientes deben finalizar antes de cerrar. Los buffers modificados de un layout cuya pestaña terminó se preservan mediante la reconciliación existente.

La revisión adicional, las ventanas enlazadas y los archivos modificados quedan sin comprobación manual nueva.
